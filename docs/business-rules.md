# 业务规则

## 1. 金额规则

1. 所有金额由服务端根据数据库当前有效数据计算，客户端提交的金额、运费、优惠一律忽略。
2. 商品金额 = Σ（SKU 单价 × 数量），单价取下单时的 `product_sku.price`。
3. 运费规则（可配置）：
   - `APP_SHIPPING_FEE=10.00`（默认固定运费）
   - `APP_FREE_SHIPPING_THRESHOLD=99.00`（商品金额满 99 元包邮；设为 0 表示始终包邮）
   - 实付 = 商品金额 + 运费 − 优惠；首版优惠固定 0。
4. 金额精度：`DECIMAL(10,2)`，中间计算使用 `BigDecimal`，最终 `setScale(2, RoundingMode.HALF_UP)`。
5. 订单明细保存商品名、规格、图片、成交单价快照；后续商品改价不影响历史订单。
6. 支付金额以订单 `payable_amount` 为准；支付记录金额必须与之一致。

## 2. 库存规则

1. 仅 `ON_SALE` 商品且 `ENABLED` SKU 可购买。
2. 加购不锁库存；结算预览不扣库存；**创建订单时扣减**。
3. 扣减使用条件更新：
   ```sql
   UPDATE product_sku
      SET stock = stock - #{qty}, updated_at = NOW(3)
    WHERE id = #{skuId} AND stock >= #{qty} AND status = 'ENABLED'
   ```
   影响行数必须为 1，否则抛 `STOCK_INSUFFICIENT`。
4. 多 SKU 按 `sku_id` 升序扣减，任一项失败整单回滚（同一数据库事务）。
5. 数据库 `CHECK (stock >= 0)` 兜底；库存不以任何方式出现负数。
6. 取消 `PENDING_PAYMENT` 订单时回补库存；仅当订单状态条件更新成功（`PENDING_PAYMENT → CANCELLED`）才执行回补，保证幂等且只回补一次。
7. 已支付订单首版不支持用户直接取消；退款/售后列入后续扩展。

## 3. 订单状态机

| 当前状态 | 操作 | 触发者 | 目标状态 | 前置条件 |
| --- | --- | --- | --- | --- |
| — | 创建订单 | USER | `PENDING_PAYMENT` | 地址有效、商品可售、库存充足、幂等键唯一 |
| `PENDING_PAYMENT` | 支付成功 | PAYMENT | `PENDING_SHIPMENT` | 金额一致、支付记录成功 |
| `PENDING_PAYMENT` | 取消 | USER/ADMIN | `CANCELLED` | 用户未超取消时限；管理员需原因 |
| `PENDING_SHIPMENT` | 发货 | ADMIN | `PENDING_RECEIPT` | 填写物流公司与单号 |
| `PENDING_RECEIPT` | 确认收货 | USER | `COMPLETED` | — |
| 其他 | 任意 | — | — | 拒绝并返回 `ORDER_STATE_INVALID` |

- 支付状态独立：`UNPAID → PAID`（模拟支付/未来真实支付），退款后 `REFUNDED`（后续）。
- 每次变更写 `order_status_log`（from/to/operator/remark）。
- 客户端只能调用语义化动作接口，不能提交目标状态。
- 状态更新使用 `WHERE status = 期望旧状态` 条件更新并检查影响行数，防止并发重复流转。

## 4. 取消与超时

- 用户可取消 `PENDING_PAYMENT` 订单，默认时限 30 分钟（`APP_ORDER_CANCEL_MINUTES`），可配置为 0 表示不限制。
- 超时自动取消：首版提供定时任务（每 5 分钟扫描超时未支付订单），取消并回补库存；任务开关可配置。若关闭，仅保留手动取消。
- 取消原因：用户可填；系统取消固定为“超时未支付”。
- 取消后订单不可恢复；重新购买需创建新订单。
- 回补只在该订单从未回补过时发生（由状态条件更新保证），日志记录。

## 5. 幂等与重复提交

1. 创建订单必须携带 `clientRequestNo`（客户端 UUID）。`(user_id, client_request_no)` 唯一索引。
2. 重复请求处理：顺序重复直接返回原订单；并发竞态由唯一索引拦截，返回 409，库存只扣减一次。
3. 前端在请求期间禁用提交按钮；服务端仍必须独立防重。
4. 模拟支付：仅 `PENDING_PAYMENT` 可支付；重复支付请求返回当前支付结果，不重复流转。
5. 未来支付回调：以 `payment_no/order_no` 幂等，校验金额、签名、状态。

## 6. 商品与分类

- 商品上架：分类启用、存在至少一个 `ENABLED` 且价格 ≥ 0 的 SKU。
- SKU 价格 ≥ 0，库存 ≥ 0，编码全局唯一。
- 商品/分类/轮播图软状态控制，用户端只读启用/上架数据。
- 分类最多两级；禁止循环父子关系；有子分类或商品时禁止删除。
- 商品被订单明细引用后禁止物理删除；可下架。
- 轮播图 `PRODUCT/CATEGORY` 跳转必须指向存在的目标。

## 7. 购物车

- 仅登录用户；一人一 SKU 一条记录，重复加购累加数量。
- 数量范围 1–99；加购时校验 SKU 存在且启用，允许加购库存暂时不足的商品但要提示（下单仍校验）。
- 结算前再次校验商品上下架、SKU 状态、库存与价格变化；失效项需用户移除或调整。
- 下单成功后删除已下单的购物车项（仅当来源为购物车）。

## 8. 地址

- 地址必须属于当前用户；下单时再次校验归属。
- 同一用户仅一个默认地址；设置默认在事务内先清除旧默认。
- 删除默认地址后不自动指定新默认。
- 订单保存地址快照，之后地址修改/删除不影响订单。
- 日志与后台列表对手机号脱敏（如 `138****8000`）。

## 9. 用户与权限

- 用户只能访问自己的购物车、地址、订单；越权返回 403/404，不泄露资源存在性。
- 管理员接口必须 `role=ADMIN`；前端隐藏按钮不构成权限控制。
- 禁用用户不能登录及调用 `/me/**`（已签发令牌在下一次请求校验状态）。
- 管理员不能读取用户密码/令牌（系统本就不存储用户密码）。
- 生产环境禁用开发登录与模拟支付，启动时校验配置。

## 10. 支付（首版）

- 定义 `PaymentGateway` 抽象；`MockPaymentGateway` 仅在 dev/test 且 `APP_PAYMENT_MOCK_ENABLED=true` 时创建，生产不加载。
- 模拟支付界面与日志明确标注“模拟支付”，不得表现为真实支付。
- 支付成功：订单 `PENDING_PAYMENT → PENDING_SHIPMENT`、支付状态 `PAID`，写 `payment_record` 与 `PAYMENT` 状态日志；金额取订单应付金额，不信任客户端。
- 重复支付：已支付订单直接返回当前订单，不重复写支付记录；并发下由订单条件更新保证只有一次生效。
- 已取消订单不可支付；已支付订单不可取消（退款/售后后续实现）。
- 未配置微信商户资料或模拟支付关闭时，支付返回明确错误，不静默成功。
- 支付证书、API v3 Key、AppSecret 只来自环境变量，不入库、不入仓库。
- 真实微信支付接入需单独验收：下单、预支付签名、回调验签、金额与商户订单号校验、幂等、对账、退款。

## 11. 图片存储

- `StorageService` 接口隔离；首版本地磁盘存储。
- 上传限制：≤ 2MB，仅 jpg/png/webp；校验内容类型与魔数；随机文件名。
- 生产建议替换对象存储适配器 + CDN；替换不影响商品/订单业务。

## 12. 日志与审计

- 所有请求生成 `requestId` 并写入响应；日志带 requestId、用户/管理员 ID、路径、耗时。
- 不记录密码、令牌、支付密钥、完整手机号、完整地址。
- 管理员关键写操作写 `admin_operation_log`。
- 生产关闭详细错误页与堆栈输出。

## 13. 配置项（业务相关）

| --- | --- | --- |
| 固定运费 | 10.00 | 元 |
| 包邮门槛 | 99.00 | 商品金额达到即免运费 |

## 14. 测试要点

- 上架过滤、搜索、分类筛选、分页、空结果。
- 未登录/越权访问被拒绝；跨用户订单与地址不可见。
- 客户端篡改价格/金额不影响服务端计算结果。
- 库存不足整单失败且无订单/明细残留。
- 并发下单不产生负库存（条件更新 + 行数校验）。
- 相同 `clientRequestNo` 不重复扣库存/建单。
- 非法状态转换被拒绝；重复取消只回补一次。
- 管理员接口拒绝普通用户令牌。
- 空库 Flyway 迁移成功；演示数据仅 dev 加载。
- 模拟支付仅在 dev 开启时可用；生产配置校验失败即拒绝启动。
