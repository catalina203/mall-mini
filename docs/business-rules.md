# 业务规则

## 1. 金额规则

1. 所有金额由服务端根据数据库当前有效数据计算，客户端提交的金额、运费、优惠一律忽略。
2. 商品金额 = Σ（SKU 单价 × 数量），单价取下单时的 `product_sku.price`。
3. 运费规则（可配置）：
   - `APP_SHIPPING_FEE=10.00`（默认固定运费）
   - `APP_FREE_SHIPPING_THRESHOLD=99.00`（商品金额满 99 元包邮；设为 0 表示始终包邮）
   - 实付 = 商品金额 + 运费 − 优惠；首版优惠固定 0。
4. 金额精度：`DECIMAL(10,2)`，中间计算使用 `BigDecimal`，最终 `setScale(2, RoundingMode.HALF_UP)`。
5. 订单明细保存商品名、规格、图片、成交单价快照；后续商品改价不影响历史订单。
6. 支付金额以订单 `payable_amount` 为准；支付记录金额必须与之一致。

## 2. 库存规则

1. 仅 `ON_SALE` 商品且 `ENABLED` SKU 可购买。
2. 加购不锁库存；结算预览不扣库存；**创建订单时扣减**。
3. 扣减使用条件更新：
   ```sql
   UPDATE product_sku
      SET stock = stock - #{qty}, updated_at = NOW(3)
    WHERE id = #{skuId} AND stock >= #{qty} AND status = 'ENABLED'
   ```
   影响行数必须为 1，否则抛 `STOCK_INSUFFICIENT`。
4. 多 SKU 按 `sku_id` 升序扣减，任一项失败整单回滚（同一数据库事务）。
5. 数据库 `CHECK (stock >= 0)` 兜底；库存不以任何方式出现负数。
6. 取消 `PENDING_PAYMENT` 订单时回补库存；仅当订单状态条件更新成功（`PENDING_PAYMENT → CANCELLED`）才执行回补，保证幂等且只回补一次。
7. 已支付订单用户不能直接取消，应通过售后流程申请退款/退货退款。
8. 所有库存变化写入 `stock_log`：订单扣减、取消回补、售后退货回补、商品初始库存、手动调整与盘点。
9. 回补按 `(change_type, biz_no, sku_id)` 幂等；重复取消或重复退款不会重复入库。

## 3. 订单状态机

| 当前状态 | 操作 | 触发者 | 目标状态 | 前置条件 |
| --- | --- | --- | --- | --- |
| — | 创建订单 | USER | `PENDING_PAYMENT` | 地址有效、商品可售、库存充足、幂等键唯一 |
| `PENDING_PAYMENT` | 支付成功 | PAYMENT | `PENDING_SHIPMENT` | 金额一致、支付记录成功 |
| `PENDING_PAYMENT` | 取消 | USER/ADMIN | `CANCELLED` | 用户未超取消时限；管理员需原因 |
| `PENDING_SHIPMENT` | 发货 | ADMIN | `PENDING_RECEIPT` | 填写物流公司与单号 |
| `PENDING_RECEIPT` | 确认收货 | USER | `COMPLETED` | — |
| 其他 | 任意 | — | — | 拒绝并返回 `ORDER_STATE_INVALID` |

- 支付状态独立：`UNPAID → PAID`；部分退款后 `PARTIALLY_REFUNDED`，整单退款后 `REFUNDED`。
- 退款不强行修改订单履约状态，订单列表通过支付状态展示“已退款/部分退款”；已退款订单禁止发货。
- 每次变更写 `order_status_log`（from/to/operator/remark）。
- 客户端只能调用语义化动作接口，不能提交目标状态。
- 状态更新使用 `WHERE status = 期望旧状态` 条件更新并检查影响行数，防止并发重复流转。

## 4. 取消与超时

- 用户可取消 `PENDING_PAYMENT` 订单，默认时限 30 分钟（`APP_ORDER_CANCEL_MINUTES`），可配置为 0 表示不限制。
- 超时自动取消：首版提供定时任务（每 5 分钟扫描超时未支付订单），取消并回补库存；任务开关可配置。若关闭，仅保留手动取消。
- 取消原因：用户可填；系统取消固定为“超时未支付”。
- 取消后订单不可恢复；重新购买需创建新订单。
- 回补只在该订单从未回补过时发生（由状态条件更新保证），日志记录。
- 自动确认收货：已发货订单超过 `APP_ORDER_AUTO_CONFIRM_DAYS`（默认 7 天）且无进行中售后时，系统自动完成并写 `SYSTEM` 日志；已退款订单不自动完成。

## 5. 幂等与重复提交

1. 创建订单必须携带 `clientRequestNo`（客户端 UUID）。`(user_id, client_request_no)` 唯一索引。
2. 重复请求处理：顺序重复直接返回原订单；并发竞态由唯一索引拦截，返回 409，库存只扣减一次。
3. 前端在请求期间禁用提交按钮；服务端仍必须独立防重。
4. 模拟支付：仅 `PENDING_PAYMENT` 可支付；重复支付请求返回当前支付结果，不重复流转。
5. 未来支付回调：以 `payment_no/order_no` 幂等，校验金额、签名、状态。

## 6. 商品与分类

- 商品上架：分类启用、存在至少一个 `ENABLED` 且价格 ≥ 0 的 SKU。
- SKU 价格 ≥ 0，库存 ≥ 0，编码全局唯一。
- 商品/分类/轮播图软状态控制，用户端只读启用/上架数据。
- 分类最多两级；禁止循环父子关系；有子分类或商品时禁止删除。
- 商品被订单明细引用后禁止物理删除；可下架。
- 轮播图 `PRODUCT/CATEGORY` 跳转必须指向存在的目标。

## 7. 购物车

- 仅登录用户；一人一 SKU 一条记录，重复加购累加数量。
- 数量范围 1–99；加购时校验 SKU 存在且启用，允许加购库存暂时不足的商品但要提示（下单仍校验）。
- 结算前再次校验商品上下架、SKU 状态、库存与价格变化；失效项需用户移除或调整。
- 下单成功后删除已下单的购物车项（仅当来源为购物车）。

## 8. 地址

- 地址必须属于当前用户；下单时再次校验归属。
- 同一用户仅一个默认地址；设置默认在事务内先清除旧默认。
- 删除默认地址后不自动指定新默认。
- 订单保存地址快照，之后地址修改/删除不影响订单。
- 待发货、已支付且无进行中售后的订单允许用户修改收货地址；更新快照并写状态日志。已发货/已退款订单不允许修改。
- 日志与后台列表对手机号脱敏（如 `138****8000`）。

## 9. 用户与权限

- 用户只能访问自己的购物车、地址、订单；越权返回 403/404，不泄露资源存在性。
- 管理员接口必须 `role=ADMIN`；前端隐藏按钮不构成权限控制。
- 禁用用户不能登录及调用 `/me/**`（已签发令牌在下一次请求校验状态）。
- 管理员不能读取用户密码/令牌（系统本就不存储用户密码）。
- 管理员角色：`SUPER_ADMIN / OPERATOR / CUSTOMER_SERVICE / WAREHOUSE`，权限矩阵由服务端维护。
- 前端菜单隐藏只是体验层，后端必须用权限码校验；不得仅靠前端控制。
- 管理员改角色、禁用、重置密码或自行改密后，递增 `token_version`，旧 JWT 失效。
- 必须至少保留一个启用的超级管理员，不能禁用自己或修改自己的角色。
- 生产环境禁用开发登录与模拟支付，启动时校验配置。

## 10. 支付（首版）

- 定义 `PaymentGateway` 抽象；`MockPaymentGateway` 仅在 dev/test 且 `APP_PAYMENT_MOCK_ENABLED=true` 时创建，生产不加载。
- 模拟支付界面与日志明确标注“模拟支付”，不得表现为真实支付。
- 支付成功：订单 `PENDING_PAYMENT → PENDING_SHIPMENT`、支付状态 `PAID`，写 `payment_record` 与 `PAYMENT` 状态日志；金额取订单应付金额，不信任客户端。
- 重复支付：已支付订单直接返回当前订单，不重复写支付记录；并发下由订单条件更新保证只有一次生效。
- 已取消订单不可支付；已支付订单不可直接取消，需走售后退款。
- 未配置微信商户资料或模拟支付关闭时，支付返回明确错误，不静默成功。
- 支付证书、API v3 Key、AppSecret 只来自环境变量，不入库、不入仓库。
- 退款：开发环境使用模拟退款；生产未接微信退款时，管理员必须填写线下退款凭证，禁止静默成功。
- 真实微信支付接入需单独验收：下单、预支付签名、回调验签、金额与商户订单号校验、幂等、对账、退款。

## 11. 图片存储

- `StorageService` 接口隔离；首版本地磁盘存储。
- 上传限制：≤ 2MB，仅 jpg/png/webp；校验内容类型与魔数；随机文件名。
- 生产建议替换对象存储适配器 + CDN；替换不影响商品/订单业务。

## 12. 日志与审计

- 所有请求生成 `requestId` 并写入响应；日志带 requestId、用户/管理员 ID、路径、耗时。
- 不记录密码、令牌、支付密钥、完整手机号、完整地址。
- 管理员关键写操作写 `admin_operation_log`。
- 生产关闭详细错误页与堆栈输出。

## 14. 售后与退款

1. 可申请条件：订单已支付，且状态为待发货、待收货或已完成；未支付、已取消、已退款订单不可申请。
2. 同一订单只允许一个进行中的售后；已退款订单不能再次申请。
3. 类型：
   - `REFUND_ONLY`：未发货或协商一致时使用，不要求寄回；
   - `RETURN_REFUND`：已发货/已完成时使用，必须填写退货物流。
4. 退款金额由服务端计算：
   - 整单全部商品全部数量：按订单实付金额（含运费）；
   - 部分商品/部分数量：按订单明细成交单价 × 数量，运费不退；
   - 不超过订单实付金额，客户端提交金额无效。
5. 状态机：

```text
APPLIED
  -> APPROVED -> REFUNDING -> REFUNDED / REFUND_FAILED
  -> WAIT_RETURN -> RETURNED -> RETURN_RECEIVED -> REFUNDING -> REFUNDED / REFUND_FAILED
  -> REJECTED
  -> CANCELLED
```

6. 仅退款：审核通过后可发起退款；退货退款：审核通过后用户填写退货物流，管理员确认收到退货后才能退款。
7. 退款渠道：
   - 开发环境 `MOCK`，明确标记模拟退款；
   - 生产未接微信退款时使用 `MANUAL`，必须填写线下退款凭证号；
   - 退款失败保留 `REFUND_FAILED`，可重试，不得假装成功。
8. 退款成功：
   - 更新 `refund_record` 为 `SUCCESS`；
   - 订单支付状态按整单/部分更新为 `REFUNDED` / `PARTIALLY_REFUNDED`；
   - 仅 `RETURN_REFUND` 按售后明细回补库存并写库存流水；
   - 写售后日志与用户通知。
9. 退款幂等：同一售后单只有一条退款记录；已退款再次请求直接返回当前结果。
10. 客户端只能调用语义化动作接口，不能提交目标状态或退款金额。

## 15. 库存流水

1. `stock_log` 记录每次库存变化的前后值、变动数量、业务类型/单号与操作人。
2. 变动类型：下单扣减、取消回补、售后退货回补、手动调整、商品初始库存、盘点。
3. 手动调整必须填写调整后库存，禁止直接改表；后台调整与商品编辑都写流水。
4. 下单与回补使用行锁 + 条件校验，库存不得为负。
5. 低库存阈值默认 10，可配置；库存从高于阈值降到阈值及以下时通知管理员。
6. 流水查询支持按 SKU、业务单号、变动类型筛选。

## 16. 站内通知

1. 当前写入 `notification_log`，渠道 `IN_APP`，状态 `SENT`，用户可通过 `/api/v1/me/notifications` 查看。
2. 事件：支付成功、订单发货、售后申请、审核通过/拒绝、退货寄回/签收、退款成功、低库存。
3. 通知内容不得包含密码、令牌、支付密钥、完整手机号/地址。
4. 微信订阅消息与短信尚未接入；接入时需模板审核、用户订阅授权、失败重试与幂等，外部发送不得放在订单事务内。
5. 管理后台可查询通知记录，便于排查失败与漏发。

## 17. 管理员权限（RBAC）

| 角色 | 权限范围 |
| --- | --- |
| `SUPER_ADMIN` | 全部权限，含管理员管理、操作日志、CSV 导出 |
| `OPERATOR` | 商品/分类/轮播图、订单、售后、库存、用户状态、导出；无管理员管理与审计 |
| `CUSTOMER_SERVICE` | 仪表盘、订单查看/备注、售后审核、用户查看、通知；无退款、库存调整、导出 |
| `WAREHOUSE` | 仪表盘、订单查看/发货、售后查看、库存查看/调整、通知 |

权限码：`DASHBOARD_READ`、`PRODUCT_READ/WRITE`、`CATEGORY_READ/WRITE`、`BANNER_READ/WRITE`、`ORDER_READ/WRITE/SHIP/CANCEL`、`AFTER_SALE_READ/REVIEW/REFUND`、`STOCK_READ/ADJUST`、`USER_READ/STATUS`、`NOTIFICATION_READ`、`ADMIN_MANAGE`、`AUDIT_READ`、`EXPORT_READ`。

- 角色变更、禁用、重置密码、自行改密都会使旧令牌失效。
- 管理员管理接口只允许 `SUPER_ADMIN`。
- 不能禁用自己或修改自己的角色；必须至少保留一个启用的超级管理员。

## 18. 履约增强

1. 自动确认收货：发货后超过配置天数且无进行中售后，系统自动完成订单并通知用户。
2. 订单后台备注：仅管理员可见，保存动作写操作日志，不进入用户订单详情。
3. 发票信息：用户下单时可选择是否需要发票，记录抬头、税号、邮箱；当前只保存信息，不自动开票。
4. 地址修改：仅待发货、已支付、无进行中售后可修改；更新快照并记录状态日志。

## 19. 导出与看板口径

- CSV 导出需要 `EXPORT_READ`，单次最多 10000 行，导出动作写操作日志。
- 订单导出手机号脱敏；用户导出手机号脱敏；库存导出不含个人信息。
- 看板口径：
  - 支付金额：区间内已支付订单应付金额（含后续退款）；
  - 退款金额：区间内成功的退款；
  - 净收入 = 支付金额 − 退款金额；
  - 客单价 = 净收入 / 已支付订单数；
  - 退款率 = 退款金额 / 支付金额；
  - 待发货、待收货、售后待处理、低库存为当前全量。
- 指标口径变更必须同步文档与后台说明，避免经营误判。

## 20. 优惠券

1. 类型：
   - `FIXED`：减免固定金额；
   - `PERCENT`：按百分比减免（`value=10` 表示减 10%）。
2. 适用范围：全场 / 指定分类 / 指定商品；指定范围只对匹配明细的商品金额计算。
3. 使用门槛按适用范围内的商品金额判断，不含运费。
4. 优惠金额不超过适用商品金额，也不超过订单商品金额；运费不参与优惠。
5. 首版每人每模板限领 1 张；模板发放总量 0 表示不限量，领取使用条件更新计数。
6. 优惠券必须未使用且在有效期内；下单成功后条件锁定为 `USED`，绑定订单号。
7. 订单取消/超时取消释放优惠券为 `UNUSED`；已支付订单退款不自动退券（首版规则）。
8. 客户端只能传 `couponId`，不能传优惠金额；服务端重新计算。

## 21. 运费模板

1. 商品可绑定运费模板；未绑定使用全局 `APP_SHIPPING_FEE` / `APP_SHIPPING_FREE_THRESHOLD`。
2. 模板规则按省份精确匹配，未匹配时使用全国规则（`region_code=''`），再退回模板默认运费。
3. 运费按首件 + 续件计算：
   `首费 + ceil(max(数量-首件,0)/续件) × 续费`。
4. 同一订单不同模板分组分别计算后相加；商品金额达到该模板/规则的包邮门槛时该组免运费。
5. 运费模板变更不影响历史订单；订单保存应付金额快照。
6. 有商品绑定的模板不能删除，可停用。

## 22. 评价、收藏与足迹

1. 仅已完成订单可评价；每个订单明细只能评价一次。
2. 评价默认 `PENDING`，审核通过后才在商品页公开；支持商家回复。
3. 评价评分 1–5 星；匿名评价公开展示为“匿名用户”。
4. 商品评分只统计 `APPROVED` 评价，平均分保留两位小数。
5. 收藏按用户+商品唯一；重复收藏幂等。
6. 浏览足迹按用户+商品唯一，重复浏览更新时间；用户可清空。
7. 商品下架/删除后，收藏与足迹展示“已下架/已删除”，不伪造数据。

## 23. 搜索

1. 关键词去首尾空格，长度不超过 64；空关键词不记录。
2. 商品搜索使用 MySQL ngram 全文索引，配合 LIKE 兜底，避免中文短词无结果。
3. 商品搜索第一页记录热词计数；同一关键词累加。
4. 热词仅用于展示与运营观察，不展示违规/敏感内容。
5. 搜索只返回上架商品与有效分类，支持分类、价格、销量/价格排序。

## 24. 会员积分

1. 订单完成后按实付金额向下取整，1 元 = 1 积分；奖励写入 `points_log`，按订单号幂等。
2. 整单退款扣回该订单奖励积分；部分退款不扣回（首版规则）。
3. 积分余额不得为负；管理员扣减时校验余额。
4. 会员等级按累计积分：普通 <100、银卡 100、金卡 500、钻石 2000。
5. 管理员调整积分写操作日志，备注可选。
6. 积分仅用于会员权益展示，首版不抵扣现金。

## 25. 客服工单

1. 登录用户可提交工单，类型：订单/商品/退款售后/其他。
2. 绑定订单号时校验订单归属；不绑定也可提交。
3. 工单状态：待处理、处理中、已回复、已关闭。
4. 管理员回复后状态变为已回复；用户或管理员可关闭。
5. 用户只能查看自己的工单。
6. 工单内容不含密码、支付密钥等敏感信息；日志不记录完整敏感信息。

## 26. 首页运营位

1. 首页返回轮播图、分类、推荐商品、新品上架、热销榜单。
2. 热销榜单按 `sales_count` 降序；销量按已支付件数累计，退款不回退（首版规则）。
3. 所有商品区块只展示上架商品；无数据时展示空态。
4. 首页快捷入口包含领券、客服、会员积分，未登录时引导登录。

## 27. 测试要点（补充）

- 已支付订单可申请仅退款/退货退款，未支付/已取消不可申请。
- 退款金额由服务端计算，客户端篡改无效。
- 同一订单重复/并发申请售后只成功一次。
- 仅退款不回补库存；退货退款在确认收货且退款成功后回补一次。
- 退款失败可重试，不产生假成功。
- 库存流水前后值连续，重复取消/退款不重复回补。
- 已退款订单不能发货。
- 用户不能查看他人售后单；管理员接口拒绝普通用户。
- 通知记录包含支付/发货/售后/退款事件，内容不含敏感信息。
- 不同管理员角色只能访问授权菜单/接口，前端隐藏不替代后端校验。
- 管理员改角色/禁用/重置密码后旧 JWT 失效；不能禁用自己或最后一个超管。
- 自动确认收货只执行一次，售后中/已退款订单跳过。
- 已发货订单不能修改地址；待发货可修改并更新快照。
- CSV 导出字段与筛选一致，手机号脱敏，导出动作写日志。
- 发票必填项校验、后台备注仅管理员可见。
- 优惠券领取唯一、超发条件更新、门槛/范围/有效期校验、下单锁定、取消释放。
- 运费模板按省份/全国匹配、首件续件计算、包邮门槛、未绑定回退全局配置。
- 评价仅已完成订单、一明细一次、审核后公开、匿名脱敏。
- 收藏/足迹幂等、清空、越权隔离。
- 搜索关键词去重计数、热词展示、中文搜索有结果。
- 订单完成积分奖励幂等；整单退款扣回；管理员调整不能造成负余额。
- 工单提交/回复/关闭、用户越权访问隔离。
- 首页新品/热销/推荐区块只含上架商品。

## 28. 测试要点

- 上架过滤、搜索、分类筛选、分页、空结果。
- 未登录/越权访问被拒绝；跨用户订单与地址不可见。
- 客户端篡改价格/金额不影响服务端计算结果。

- 管理员接口拒绝普通用户令牌。
